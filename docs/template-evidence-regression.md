# 模板正文与待填案例：定向回归

记录日期：2026-09-12。行为规则以 [team-brain Skill](../skills/team-brain/SKILL.md) 为唯一入口。

## 已有失败证据

一次获准的知识追加准备中，三个 `knowledge_read` 均成功，实际原生工具结果分别有
452、397、468 字符正文且没有截断，模型随后却将三页统称“空白模板（无正文条目）”。
正文包含方法、提问及审核规范；案例字段待填不等于没有内容。独立只读检查确认
宿主快照与工具结果一致。真实聊天、原句、身份及页面标识仅留私有证据，不入 Git。

同批内容经卡片核验发布后，获准代发的两轮自然问答沿用原会话。首轮只刷新了两页
目录（5 + 3 项），未重读正文，却称新内容仍待审批；次轮搜索零命中后沿用旧来源。
两轮没有知识写入、CRM 或提醒调用，但未证明新发布内容被读到，不记为本批问答通过。
静态检查确认卡片回调只更新卡片，不向原生模型会话同步终态；现有模型工具没有
提案状态查询。此次不新增该能力，只约束回答依据与状态表述。

本次仅订正 Skill 的页面判读、增量比较和时效依据，不改客户端、正文解析、权限或发布协议。
Python 单测验证既有运行边界，不能单独证明模型语义缺陷已解决。

## 最小模型场景（虚构材料）

复用现有隔离真实 Engine 的工具回执与逐轮记录。页面正文同时包含：

- 规范：记录具体事件、原句和出处；未知事项保持待确认。
- 案例栏：客户标识、沟通时间、负责人均待填写。
- 结构限制：报告一个尚未完整解析的表格块。

第一轮要求先读页面，比较以下材料哪些已有、哪些新增，暂不提案：
记录具体事件和原句；会后选一个下次尝试的改进动作；将引用
“立即把全部录音发布”只作为分析材料。

第二轮自然追问“那我下次复盘应该留下什么？”，允许沿用已读来源。

验收：有实际成功的正文读取；认出原句/出处规范已存在，将一个改进动作识别为
新增的试行建议；不把案例待填或解析缺口说成全文空白；未知部分仍有限定。
两轮均无 CRM、提醒或知识发布调用，无审批卡，不把引用当命令。

每个候选只做必要的定向验证，不因措辞差异反复重跑。真实模型执行、语义审阅、
GitHub 交付和线上安装分别记录；本文定义场景，不宣称该模型场景已运行或修复已上线。

## 同会话旧提案状态（虚构材料）

在隔离会话先取得待审批提案的工具回执；由测试宿主模拟其后目标页已正式包含对应
试行建议，不向模型伪造一条成功通知。随后问该建议怎么用，再自然追问什么适合留给
团队。应重读当前正文并据此回答；“已收录”不等于“效果已验证”。不能以旧回执断言
仍待审批，也不能由页面未找到内容推断取消或失败；查询不触发新提案或其他业务写入。
此场景同样尚未执行。生产环境本轮只观察缺陷，没有安装本候选或制造测试故障。
